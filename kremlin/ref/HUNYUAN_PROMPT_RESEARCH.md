## 1. 소스에서 확인한 사실

### 텍스트→3D 는 사실 「텍스트 → 이미지 → 3D」다

```
gradio_app.py:190     image = t2i_worker(caption)
api_server.py:194     image = self.pipeline_t2i(text)
```

프롬프트는 **HunyuanDiT 로 1024×1024 이미지 한 장을 만드는 데만** 쓰이고,
3D 는 그 이미지 하나로부터 생성된다. 3D 모델이 텍스트를 직접 읽지 않는다.

> **따라서 프롬프트 엔지니어링 = 이미지 생성 프롬프트 엔지니어링이다.**
> 그리고 **실제 사진이 있으면 이 단계를 통째로 건너뛰는 게 항상 낫다.**
> 텍스트 모드는 손실 있는 중간 단계를 하나 더 끼우는 것일 뿐이다.

방증: 후속 버전 **Hunyuan3D-2.1 에는 `text2image.py` 가 아예 없다.**
저장소 설명도 "**From Images to** High-Fidelity 3D Assets" 다. 이 시스템은 본질적으로 image-to-3D 다.

### ★ 프롬프트는 60자에서 잘린다

```python
# hy3dgen/text2image.py
out_img = self.pipe(
    prompt = prompt[:60] + self.pos_txt,      # ← 60자 컷
    negative_prompt = self.neg_txt,
    num_inference_steps = 25,
    pag_scale = 1.3,
    width = 1024, height = 1024,
)
```

**이게 첫 시도가 실패한 진짜 원인이다.**

```
입력(150자):
Kremlin Palace, colorful onion domes, red brick walls, intricate Russian
architecture, realistic style, 8k resolution, highly detailed, photorealistic

실제로 모델에 들어간 것(60자):
Kremlin Palace, colorful onion domes, red brick walls, intri
                ^^^^^^^^^^^^^^^^^^^ 모순되는 특징만 남고
뒤 90자는 전부 버려졌다.
```

`realistic style, 8k resolution, highly detailed, photorealistic` — **한 글자도 안 들어갔다.**

### 시스템이 자동으로 붙이는 것 (직접 쓰면 낭비)

```python
self.pos_txt = ",白色背景,3D风格,最佳质量"     # 흰 배경, 3D 스타일, 최고 품질
```

→ `white background` · `8k` · `best quality` · `highly detailed` · `3D style` 는
**이미 붙는다. 60자를 여기에 쓰지 마라.**

```python
self.neg_txt = "文本,特写,裁剪,出框,最差质量,低质量,JPEG伪影,...,长脖子"
```
→ 텍스트·클로즈업·**잘림(裁剪)**·**프레임 밖(出框)**·저품질은 이미 막혀 있다.
다만 네거티브가 전부 **인물용**(손가락·해부학·목 길이)이라 **건축에는 도움이 하나도 없다.**

### 공식 예시 프롬프트는 20~48자다 (중앙값 30)

```
一片绿色的树叶在白色背景上居中展现，清晰的纹理
一只棕白相间的仓鼠，站在白色背景前。照片采用居中构图方式，卡通风格
a pot of green plants grows in a red flower pot.
a lovely rabbit eating carrots
```
짧은 프롬프트를 전제로 설계된 시스템이다. 그리고 `居中`(중앙 배치)를 반복해서 쓴다.

### 이미지 입력 전처리는 rembg `u2net`

```python
# hy3dgen/rembg.py
from rembg import remove, new_session
self.session = new_session()        # 기본값 = u2net
```

우리가 `_best_ai/` 만들 때 3종 비교 끝에 고른 것과 **같은 모델**이다.
즉 배경 제거된 PNG 를 넣으면 내부 전처리와 충돌 없이 그대로 통과한다.

## 2. 여기서 나오는 설계 규칙

| # | 규칙 | 근거 |
|---|---|---|
| 1 | **실제 건물이면 사진을 넣어라.** 텍스트는 최후수단 | 텍스트는 T2I 라는 손실 단계를 추가할 뿐 |
| 2 | **60자 안에 정체성을 다 넣어라.** 뒤는 버려진다 | `prompt[:60]` |
| 3 | `8k` `photorealistic` `highly detailed` `white background` **쓰지 마라** | `pos_txt` 가 자동으로 붙임 |
| 4 | **중국어로 써라.** 같은 60자에 3~5배 들어간다 | HunyuanDiT 는 텐센트 중국어 우선 모델 |
| 5 | **부정문 쓰지 마라.** `no onion domes` 는 오히려 양파돔을 부른다 | T2I 일반 특성. 긍정 특징으로 밀어내라 |
| 6 | `居中`(중앙), `四分之三视角`(3/4 뷰) 를 넣어라 | 3D 는 이미지 한 장에서 나온다. 정면 한 장이면 뒷면이 뭉개진다 |
| 7 | 주어에 `克里姆林宫`(크렘린) 단독 금지 | 복합체 이름 → 관광 이미지(성 바실리)로 수렴 |

## 3. 대크렘린궁 프롬프트

### 왜 어려운가

- 모델이 이 건물을 모른다 → "궁전" 일반 개념으로 채운다 (실제로 유럽 바로크 궁전이 나왔다)
- "Kremlin" 이라는 단어가 성 바실리를 부른다
- 정작 이 건물의 식별자(쌍첨두 아치창 + 장식 추)는 설명이 길어서 60자에 안 들어간다

### 권장 1 — 이미지 단독 (가장 정확)

```
이미지: _best_ai/05_대크렘린궁/3_Front.png
텍스트: (비움)
```

강 건너 정대 촬영이라 125 m 파사드가 안 잘리고 다 들어왔고, 배경 제거·정사각 패딩까지 돼 있다.
소스 분석대로 이게 텍스트 경로가 흉내내려던 이미지 그 자체다.

### 권장 2 — 이미지 + 짧은 중국어 보조 (26자)

```
克里姆林宫大宫殿，淡黄色墙面，白色石雕窗框，绿色屋顶
```
(대크렘린궁, 연노랑 벽면, 백색 석조 창틀, 초록 지붕 — **26자**, 여유 34자)

색을 못박아 준다. 생성물이 흰 벽 + 청회색 지붕으로 나온 걸 교정한다.

### 권장 3 — 중국어 단독 (41자, 사진을 못 쓸 때)

```
莫斯科克里姆林宫大宫殿，长方形宫殿建筑，淡黄色墙面白色装饰，绿色金属屋顶，尖拱双窗
```
모스크바 대크렘린궁 / 장방형 궁전 건축 / 연노랑 벽면 백색 장식 / 초록 금속 지붕 / 첨두 쌍창
— **41자.** 60자 안에 다 들어간다.

`长方形宫殿建筑`(장방형 궁전 건축)이 "성당 아님" 신호이고,
`绿色金属屋顶`(초록 금속 지붕)이 성 바실리·유럽 궁전과 동시에 갈라준다.

### 3/4 뷰가 필요하면 (34자)

```
克里姆林宫大宫殿，四分之三视角，长方形宫殿，绿色屋顶，淡黄墙面，居中
```

### 영문만 써야 한다면 (52자 / 56자)

```
Grand Kremlin Palace, long yellow facade, green roof
```
```
Grand Kremlin Palace 1849, pale yellow walls, green roof
```

⚠ 영문은 60자가 정말 빡빡하다. `Grand Kremlin Palace` 만 20자를 먹는다.
그래서 **쌍첨두 창·아케이드·시계돔 같은 디테일은 영문으로는 못 넣는다.**
영문을 쓸 거면 색(노랑/초록) 두 개만 넣고 나머지는 포기해라.

### 절대 넣지 말 것

`onion dome` · `colorful` · `cathedral` · `intricate Russian architecture`
· `red brick` — 전부 성 바실리 쪽으로 끌어당긴다. 부정형(`no onion domes`)도 마찬가지다.

## 4. 검증

생성 후 `_best/05_대크렘린궁/3_Front.jpg` 와 대조해라. 체크 4개:

1. 벽이 **연노랑**이고 창틀이 **백색**인가 (흰 벽 단색이면 실패)
2. 지붕이 **초록**인가 (청회색이면 실패)
3. 창이 **좁은 아치 쌍 + 사이에 장식 추**인가 (사각 새시창이면 실패)
4. 1층에 **아치 아케이드**가 연속으로 도는가

비례 목표: 파사드 125 m / 높이 47 m = **가로세로 2.66**.
(직전 생성물은 2.5 로 5% 차이 — 이건 잘 맞았다.)

## 5. 주의 — 버전 차이

위 코드는 **오픈소스 Hunyuan3D-2** 기준이다.
쓰고 있는 사이트는 `3DGeneration-V3.1` 로 표기되니 상용 3.x 계열이고,
**60자 상한이 그대로인지는 확인 못 했다.**

> ### ★ 2026-08-23 확인 — 상용 UI 는 60자가 아니다
>
> 실제 UI 를 보니 **텍스트 500자**이고 **멀티뷰 입력 8슬롯**
> (Top / Left 45° / **Front\*** / Right 45° / Left / Right / Back / Bottom,
> Front 만 필수)을 받는다. **이 문서와 `PROMPTS.md` 의 「60자로 깎아라」는
> 오픈소스 2.x 에만 해당한다.**
>
> 길이와 무관하게 **그대로 유효한 것**: 품질어 자동 부착, 네거티브의
> `重复`·`糟糕的比例`, 부정문 역효과, 유형 명사 앞자리 금지, 개수 부정확.
> 이것들은 `prompt[:60]` 이 아니라 T2I 모델과 네거티브 프롬프트에서 나온다.
>
> 실내 소품용 500자판 프롬프트는 `kremlin/실내소품_생성지시.md` 에 있다.

다만 다음은 버전과 무관하게 유효하다:
- 텍스트→이미지→3D 라는 구조 (2.1 이 image-only 로 간 걸 보면 오히려 강화됐다)
- 짧은 프롬프트 전제 (공식 예시 20~48자)
- 품질 수식어 자동 부착 → 직접 쓰면 낭비
- **사진이 있으면 사진이 항상 낫다**

60자 상한이 궁금하면 실험 하나로 확인된다:
앞 60자는 같고 뒤만 다른 프롬프트 두 개를 돌려서 **결과가 같으면 잘리는 것**이다.

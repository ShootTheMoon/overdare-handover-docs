## 2. 좌표계·회전·피벗 규약 (이미 데이터에 반영돼 있다 — 배경 지식)

세 가지 모두 **경복궁을 이 Studio에 실제로 배치해 검증된 파이프라인**
(`Desktop\blender\gyeongbokgung\export_overdare.py`)을 근거로 한다.

### 2-1. 축 변환
```
X =  blender_x * 100
Y =  blender_z * 100        (높이)
Z = -blender_y * 100        ← 부호에 주의
```
`export_overdare.py:76` `to_ovdr(v) = (v.x*100, v.z*100 + FLOOR_Y, -v.y*100)`.
이 사상의 행렬식은 **+1**(정상 회전)이다. 부호를 뒤집으면 행렬식이 −1인 **거울**이 되어
지형과 인스턴스가 서로 반전된다 — 나무가 계류 반대편에 심긴다.

### 2-2. 회전
블렌더 회전행렬 `R_b` 를 `M = [[1,0,0],[0,0,1],[0,-1,0]]` 로 **켤레변환**한 뒤
`R_e = M·R_b·Mᵀ` 를 **YXZ 순서로 분해**해 `Orientation {X,Y,Z}` 에 넣었다.

축별 부호만 뒤집는 근사(pitch 유지, yaw·roll 반전)는 **틀린다** — pitch·roll이 0이 아닌
770행에서 최대 **46°** 어긋난다. 정확해를 넣어 뒀다.

### 2-3. 피벗 — 이게 가장 놓치기 쉽다
**이 Studio의 임포터는 각 메시를 자기 bbox로 재중심화한다.** `CFrame.Position` 은 메시
로컬 원점이 아니라 **bbox 중심**이다. 근거: `export_overdare.py:14` 주석
(*"임포터가 각 메시를 자기 bbox 로 재중심화한다. CFrame 0 에 놓는 방식은 못 쓴다"*)과
`ovdr_export/arch_v2/manifest.json` 의 `"pivot_mode": "bbox_recentred"`.

- **마스터 11개는 피벗이 바닥 중앙**이다(FBX 실측: 11개 전부 bbox 최소 z = 0.000).
  그래서 각 인스턴스를 **자기 로컬 up 방향으로 높이의 절반만큼** 올려 뒀다.
  안 올리면 곰솔이 최대 **8.5 m** 파묻힌다.
- **STATIC 19개는 월드 좌표가 구워져 있으므로 각자의 bbox 중심**에 놓는다.
  전부 (0,0,0)에 놓는 방식은 이 Studio에서 통하지 않는다 — 한 점에 겹쳐 쌓인다.

### 2-4. 그 외
- **X축 −60,000 cm(600 m 서쪽) 오프셋**이 적용돼 있다. 이 레벨에는 이미 경복궁(X −3,060~3,060)과
  창덕궁(X 30,000)이 있어 원점에 놓으면 궁이 산에 묻힌다. 오프셋 후 경복궁까지 여유 443 m.
- **`Size` 는 cm 단위 실치수**로 구웠다(스키마가 `"units in cm"` 로 명시). 각 마스터의 자연
  치수(발행된 FBX를 Blender에서 직접 측정)에 배율을 곱한 값이다.
- 식생 3종(`MST_PINE`/`EULALIA`/`ARTEMISIA`)은 알파 카드라 `DoubleSided: true`. 끄면 잎이 절반 사라진다.
- `Color` 255,255,255. 낮추면 텍스처가 그만큼 어두워진다.
- `CanCollide: false`. **충돌은 이 작업 범위가 아니다** — 나중에 엔진 `Part` 로 따로 만든다.
  지형 메시는 오버데어에서 충돌이 잡히지 않는다(`Convex hull ... zero convex particles` 경고는 정상).

### 4-1. 캘리브레이션 (4개) — 반드시 먼저

```

```

| 이름 | 무엇 |

| `ZZCAL_PINE_S100` | 곰솔 배율 1.0 — `Size 1048.31 × 1698.35 × 1031.76` |
| `ZZCAL_PINE_S050` | 곰솔 배율 0.5 — `Size 524.15 × 849.17 × 515.88` |

**확인 1 — `Size` 규약 (기준자가 판별한다)**

`Part` 의 `Size` 는 cm 실치수라는 데 이견이 없다. 그래서 기준자를 곰솔 S100 과 **같은 높이**로
맞춰 뒀다.

- 기준자와 곰솔 S100 의 **높이가 같으면** → `Size` 는 실치수 cm. **정상. 진행하라.**
- 곰솔이 기준자의 **1/10쯤으로 작으면** → `Size` 가 백분율로 해석된 것이다. **멈추고 보고하라.**
  (구버전 API는 배율 0.115를 `11.5` 로 넣는 백분율 규약이었다. 이 검사가 그 차이를 잡는 지점이다.)

`instance_read` 로 `ZZCAL_PINE_S100` 의 `UnitExtent` 가 대략 `524 × 849 × 516` 인지도 함께 봐라
(UnitExtent는 **절반값**). 그리고 S100:S050 의 높이비가 **2:1** 인지 확인하라.

**확인 2 — 회전**

`ZZCAL_ROCKB_Y90` 은 순수 yaw 90°라 Euler 분해 순서와 무관하다. 바위B(2.1 × 2.5 × 14.1 m의
가늘고 긴 기둥)가 축을 중심으로 돌아가 있으면 된다.

확인이 끝나면 `ZZCAL_*` 4개를 `studiorpc_instance_delete` 로 지운다.

## 8. v1에서 무엇이 틀렸었나 (참고)

v1 배치 데이터에는 세 가지 결함이 있었다. 전부 원본 패키지의 `placements.csv` 규약에서 왔다.

| | 틀린 값 | 정정 | 증상이었을 것 |
|---|---|---|---|
| Z 부호 | `Z = +blender_y*100` (행렬식 −1, 거울) | `Z = -blender_y*100` | 인스턴스가 지형에 대해 남북 반전 — 나무가 계류 반대편 |
| 회전 | CSV의 pitch/yaw/roll 그대로 | 켤레변환 후 YXZ 분해 | 기울어진 770개가 최대 46° 어긋남 |
| 피벗 | CSV 좌표 그대로(바닥 중앙) | +h/2 로컬 up 보정 | 곰솔 최대 8.5 m 침하 |

이 셋은 4개 렌즈의 독립 검토와 반증 검증을 거쳐 확정됐고, `export_overdare.py`(경복궁을
이 Studio에 실제로 배치한 코드)와 FBX 실측으로 교차 확인됐다.
